# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Firmware for the Waveshare ESP32-S3-Knob-Touch-LCD-1.8, a dual-MCU desk audio streamer (AirPlay on the S3 / A2DP on the ESP32 / USB-C UAC2 on the S3) with an LVGL touch+knob UI. [spec.md](spec.md) has the full hardware facts, pin mapping, protocol design, and mode behavior that drove this repo's structure — read it before making architectural changes; it is denser and more authoritative than anything below.

## Build / run commands

Three PlatformIO environments in a single `platformio.ini`, sharing one `src/` tree:

```bash
pio run -e s3 -t upload      # flash ESP32-S3 (UI, AirPlay, USB owner)
pio run -e esp32 -t upload   # flash ESP32-U4WDH (Bluetooth/A2DP owner)
pio run -e native -t exec    # build + run the LVGL UI on desktop (no hardware)
```

Drop `-t upload`/`-t exec` to just compile. `pio run -e <env>` builds a single target instead of all three.

Both espidf envs pin pioarduino's platform release by URL in `platformio.ini` (55.03.312-1, ESP-IDF 5.5.5) — it's the first release compatible with PlatformIO Core 6.2's SCons 4.11. Older pioarduino releases fail under Core 6.2 with `ModuleNotFoundError: No module named 'SCons.Tool.FortranCommon'`.

`sdkconfig.s3` / `sdkconfig.esp32` are generated; `sdkconfig.defaults.<env>` only seeds options *missing* from them. After changing a defaults file, delete the matching `sdkconfig.<env>` (unless it holds menuconfig changes you want to keep) so it regenerates.

## Architecture

**Dual MCU, single active audio source.** ESP32-S3 (UI/AirPlay/USB) and ESP32-U4WDH (Bluetooth) are separate chips, separate firmware, separate PlatformIO environments — never assume code in one runs on the other. They talk over a dedicated UART (control/metadata only, never audio) and share nothing at the code level except `lib/common/`.

- **`src/s3/`** — ESP32-S3: LVGL UI, LCD/touch driver, encoder, WiFi + AirPlay (RAOP/ALAC) + SNTP, I2S out, CH445P source-select GPIO, USB UAC2 (TinyUSB, not yet implemented). This is also the only part of the firmware that runs on desktop (see native target below).
- **`src/esp32/`** — ESP32-U4WDH: Classic BT/A2DP sink + AVRCP target/controller for volume sync and play/pause, own encoder/volume logic. Bluetooth only — it never brings WiFi up (no PSRAM, so AirPlay lives on the S3; see spec.md §1). No native/desktop equivalent — this MCU has no UI to emulate.
- **`lib/common/`** — code shared by both MCUs: `protocol.h`/`protocol.c`, the inter-MCU UART frame format (`[SYNC 0x7E][TYPE][LEN][PAYLOAD...][CRC8]`, CRC8 over TYPE+LEN+PAYLOAD), the `wireless_state_t` struct (`MSG_STATE_UPDATE`, also used locally on the S3 for AirPlay state with `source = SOURCE_AIRPLAY`) and `track_info_t` (`MSG_TRACK_INFO`), plus the one S3→ESP32 frame, `MSG_COMMAND` (`command_t`, currently only `CMD_PAUSE`). It also holds the shared frame encoder (`protocol_encode()`) and byte-at-a-time parser (`protocol_parser_feed()`) both ends use — don't reimplement framing per MCU. Type 0x02 (the old ESP32→S3 NTP relay) is retired; don't reuse it. Auto-linked into every PlatformIO env — if you change the wire format, both `s3` and `esp32` firmware must agree, so edit it once here.

**Control ownership**: whichever MCU owns the active audio path (A2DP → ESP32; AirPlay/USB → S3) also owns its own encoder and volume state for that mode; the other MCU is a display/touch-passthrough peripheral. Don't add cross-MCU polling for input that already has an ownership rule — see spec.md's "Control ownership rule" for the reasoning.

**Source separation via `src/CMakeLists.txt`, not `build_src_filter`**: ESP-IDF's CMake build ignores PlatformIO's `build_src_filter` entirely (it silently globs all of `src/` otherwise) — the two MCU targets are separated by `src/CMakeLists.txt`, which each espidf env points at its half of the tree via `-DAK_TARGET=s3|esp32` (`board_build.cmake_extra_args` in `platformio.ini`). The glob is non-recursive; the S3 branch explicitly adds `s3/raop/` and `s3/alac/`. That file also has to declare a matching `idf_component_register()` call during ESP-IDF's "early expansion" pass (a separate `cmake -P` invocation that can't see `-DAK_TARGET`) or the real pass silently drops the component from the build — see the comments in that file before touching it. `env:native` doesn't go through any of this; it's plain PlatformIO source filtering (`platform = native`, not `espidf`).

**Per-env sdkconfig defaults**: `sdkconfig.defaults.esp32` (BT/A2DP) and `sdkconfig.defaults.s3` (16 MB flash, 8 MB octal PSRAM, `partitions_s3.csv`, 1 kHz FreeRTOS tick, socket count) live in the project root, wired in via the same `board_build.cmake_extra_args` (`-DSDKCONFIG_DEFAULTS=...`) — PlatformIO's `custom_sdkconfig` ini option is Arduino-only and silently no-ops under `framework = espidf`, so don't reach for it here. The S3 needs PSRAM enabled: `lcd_driver.c` allocates its draw buffers from it, and the AirPlay buffers (~1.3 MB) live there.

**esp32 A2DP sink** (`src/esp32/`): `bt_gap` brings up Bluedroid (Classic BT only, Just Works pairing — no display/keypad on this device); `a2dp_sink` handles connection/audio-state events and feeds decoded PCM to `i2s_out` (I2S TX on IO25/26/27, reconfigured per the negotiated SBC sample rate); `avrcp_target` is the absolute-volume target the phone pushes/pulls volume through; `avrcp_controller` sends play/pause passthrough commands from the local button (its "is it playing" state is a local guess, not authoritative — no metadata/registration wired up); `encoder` reads `EC2_A`/`EC2_B` via the PCNT quadrature decoder for local volume, and treats both lines going low at once as the `SW1` button (that's how it's wired — a short-to-GND across both encoder pins, not a separate GPIO); `app_state` is the single locked source of truth for the A2DP `wireless_state_t`, read by `state_sync` to push to the S3 over UART (33ms on change, unconditional resync every ~1s, per spec.md §2); `state_sync` also runs the UART RX task that hands `MSG_COMMAND` frames to `main.c` (`CMD_PAUSE` → AVRCP pause, or drop the A2DP link if the phone has no AVRCP controller); `bt_app_core` is the Bluedroid callback→task work-dispatch queue every BT/A2DP/AVRCP handler in this codebase re-enters through, vendored from Espressif's own (Unlicense/CC0) example code rather than hand-rolled.

**s3 WiFi + NTP** (`src/s3/wifi.c`, `src/s3/wifi_portal.c`, `src/s3/ntp.c`): the only place in this repo that brings up WiFi. `wifi.c` joins as a station (power save off for AirPlay) using credentials from NVS namespace `wifi`, falling back to the optional dev-only `CONFIG_AK_WIFI_SSID`/`CONFIG_AK_WIFI_PASSWORD` (`src/Kconfig.projbuild`). With no credentials -- or none that connect within 60 s of boot -- it enters setup mode: APSTA with a WPA2 hotspot `AudioKnob-XXXX` (random password per boot), shown on screen as a standard `WIFI:` join QR via `wifi_get_setup_info()` → `ui_show_wifi_setup()` (the setup screen becomes the UI's home screen). `wifi_portal.c` is the captive portal (DNS catch-all + HTTP setup page; everything else redirects to it so iOS/Android pop it up) and talks to `wifi.c` only through `wifi_portal_ops_t`. Submitted credentials are tried live; on GOT_IP they're saved to NVS and the device restarts into normal mode. In setup mode saved credentials keep being retried every 30 s, so a router that boots slower than the device doesn't strand it. There's no "forget network" gesture yet. SNTP (`ntp.c`) sets the system clock itself and takes servers from DHCP (`CONFIG_LWIP_DHCP_GET_NTP_SRV`); `ntp_is_synced()` gates the clock display. Time is UTC everywhere except display.

**s3 AirPlay** — layered so each piece has one job:
- `src/s3/raop/` — the AirPlay 1 receiver, ported from philippe44's MIT-licensed squeezelite-esp32 `raop` component (attribution kept in each file): `raop.c` (mDNS `_raop._tcp` advert, RTSP session, Apple-Challenge/AES-key RSA via mbedtls, DACP remote discovery + commands), `rtp.c` (HairTunes-derived RTP audio/control/timing, reorder + resend, sender clock sync, ALAC decode into a PSRAM ring), `http_util.c`, our own `dmap.c` (metadata) and `alac_dec.cpp` (C shim over Apple's decoder). Emits typed `raop_event_t`s and PCM with a per-frame playtime; knows nothing about the rest of the app.
- `src/s3/alac/` — Apple's ALAC decoder (Apache-2.0), vendored **unmodified** from macosforge/alac; built with `TARGET_RT_LITTLE_ENDIAN=1` and warnings suppressed in `src/CMakeLists.txt`. Don't edit it — fix things in `alac_dec.cpp`.
- `airplay_player.c` — holds PCM until its playtime (~2 s ahead, PSRAM ring), writes it to `audio_out`, skips/pads a few ms when the averaged error drifts past 10 ms, applies the cubic software volume.
- `airplay.c` — app glue: session/playing/volume/track state (`airplay_get_state()` returns a `wireless_state_t` so `ui_update_wireless()` renders it unchanged), DACP control task (knob volume coalesced, play/pause, preempt-pause).
- `audio_out.c` — S3 I2S TX on GPIO39/40/41, 44.1 kHz fixed; USB UAC2 should reuse it. `audio_source.c` — CH445P GPIO0 and "last source to start playing wins" arbitration (watches the ESP32's UART-reported `playing` edge; sends `CMD_PAUSE` when AirPlay displaces a playing A2DP stream). `knob.c` — S3 encoder EC1 + SW2. `main.c` decides whose state is shown and whom the S3 knob drives (`airplay_in_front()`).

**s3 UART link** (`src/s3/uart_link.c`): the S3 end of UART_NUM_1 (GPIO48 TX/GPIO38 RX; the schematic net names read the other way, verified on hardware). Its RX task parses frames with the shared parser and — per spec.md §2's decoupling design — only writes into shared state rather than calling into `ui.c` directly: `MSG_STATE_UPDATE` and `MSG_TRACK_INFO` frames land in mutex-guarded structs read via `uart_link_get_latest()` / `uart_link_get_latest_track()`. `uart_link_send_command()` sends `MSG_COMMAND` frames (fire-and-forget; the effect shows up in the next state update). Touch passthrough should add new `protocol_cmd_t` values rather than new frame types.

**Native LVGL target (`env:native`)**: only `src/s3/ui.c` + `src/s3/main_native.c` build here, against SDL2 (Homebrew, `pkg-config sdl2`) instead of the real QSPI LCD driver. `src/s3/ui.c` must stay platform-agnostic (LVGL API only — no ESP-IDF, no hardware headers) so it compiles unchanged for both the real S3 target and this emulator. `src/s3/main.c` (ESP-IDF, real hardware) and `src/s3/main_native.c` (SDL, desktop) are kept as separate entry-point files rather than one `#ifdef`-laden file, since `app_main()` vs `main()` have fundamentally different signatures and init sequences.

**UI fonts and source switching**: text uses Inter (OFL) pre-rasterized into `src/s3/font_inter_*.c` (declared in `fonts.h`; Montserrat stays for `LV_SYMBOL_*` glyphs). Regenerate with `lv_font_conv --bpp 4 --format lvgl --no-compress --lv-fallback lv_font_montserrat_14` from `@fontsource/inter` `.woff` files; native's `build_src_filter` picks them up via `+<s3/font_*.c>`. Tapping the wireless screen's status row opens the switch screen (AirPlay/Bluetooth; USB is not offered yet); `ui_set_source_handler()` reports the pick to `main.c`, which claims/releases the DAC through `audio_source` and holds the pick (`s_pick`) until the other source starts playing.

`include/lv_conf.h` is the one shared config both `s3` and `native` compile against; the single point of divergence (`LV_USE_SDL`) is gated behind `#ifdef AK_NATIVE`, defined only in `env:native`'s `build_flags`. Don't fork this file — add new native-only behavior the same way, behind `AK_NATIVE`. `env:s3` needs `lv_conf.h` visible to the `lvgl` library too, which (being a plain PlatformIO lib, not an ESP-IDF component that requires ours) can't see project's `include/` by default — `src/CMakeLists.txt` adds it to every component's compile flags via `idf_build_set_property(COMPILE_OPTIONS ...)` for that reason; don't remove it.

On real hardware `src/s3/lcd_driver.c` brings up the ST77916 QSPI panel, CST816S touch and the LVGL task. Three panel quirks it handles, all learned from garbled output: the panel needs Waveshare's own init table (`lcd_init_cmds.h`, not the driver default), every flush window must start on an even and end on an odd pixel (LVGL rounder on `LV_EVENT_INVALIDATE_AREA`), and RGB565 is byte-swapped before sending; QSPI runs at 20 MHz because 40 MHz shows pixel noise on this board. `main.c` calls `ui_init()` under the LVGL lock and polls state into `ui_update_*()` on a 33 ms LVGL timer.

## Toolchain notes

- ESP-IDF framework (via PlatformIO), not Arduino — Arduino-ESP32's TinyUSB build doesn't compile `CFG_TUD_AUDIO`, so USB Audio Class (Mode B) requires ESP-IDF.
- `env:s3` and `env:esp32` boards (`esp32-s3-devkitc-1`, `esp32dev`) are generic placeholders. The S3's real flash/PSRAM config comes from `sdkconfig.defaults.s3` (16 MB / 8 MB octal); the ESP32-U4WDH side's (4 MB embedded flash, no PSRAM) from `sdkconfig.defaults.esp32` + `partitions_esp32.csv` (3 MB factory app; Bluedroid alone is ~1 MB).
- `env:native` requires SDL2 on the host (`brew install sdl2` on macOS); its `build_flags` hardcode Homebrew's `/opt/homebrew` prefix.
