# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Firmware for the Waveshare ESP32-S3-Knob-Touch-LCD-1.8, a dual-MCU desk audio streamer (AirPlay on the S3 / A2DP on the ESP32 / USB-C UAC2 on the S3) with an LVGL touch+knob UI. [spec.md](spec.md) has the full hardware facts, pin mapping, protocol design, and mode behavior that drove this repo's structure — read it before making architectural changes; it is denser and more authoritative than anything below.

## Build / run commands

Three PlatformIO environments in a single `platformio.ini`, sharing one `src/` tree:

```bash
pio run -e s3 -t upload      # flash ESP32-S3 (UI, AirPlay, USB owner)
pio run -e esp32 -t upload   # flash ESP32-U4WDH (Bluetooth/A2DP owner)
pio run -e native -t exec    # build + run the LVGL UI on desktop (no hardware)
```

Drop `-t upload`/`-t exec` to just compile. `pio run -e <env>` builds a single target instead of all three.

Both espidf envs pin pioarduino's platform release by URL in `platformio.ini` (55.03.312-1, ESP-IDF 5.5.5) — it's the first release compatible with PlatformIO Core 6.2's SCons 4.11. Older pioarduino releases fail under Core 6.2 with `ModuleNotFoundError: No module named 'SCons.Tool.FortranCommon'`.

`sdkconfig.s3` / `sdkconfig.esp32` are generated; `sdkconfig.defaults.<env>` only seeds options *missing* from them. After changing a defaults file, delete the matching `sdkconfig.<env>` (unless it holds menuconfig changes you want to keep) so it regenerates.

## Architecture

**Dual MCU, single active audio source.** ESP32-S3 (UI/AirPlay/USB) and ESP32-U4WDH (Bluetooth) are separate chips, separate firmware, separate PlatformIO environments — never assume code in one runs on the other. They talk over a dedicated UART (control/metadata only, never audio) and share nothing at the code level except `lib/common/`.

- **`src/s3/`** — ESP32-S3: LVGL UI, LCD/touch driver, encoder, WiFi + AirPlay (2 and 1) + SNTP, I2S out, CH445P source-select GPIO, USB UAC2 (TinyUSB, not yet implemented). This is also the only part of the firmware that runs on desktop (see native target below).
- **`src/esp32/`** — ESP32-U4WDH: Classic BT/A2DP sink + AVRCP target/controller for volume sync and play/pause, own encoder/volume logic. Bluetooth only — it never brings WiFi up (no PSRAM, so AirPlay lives on the S3; see spec.md §1). No native/desktop equivalent — this MCU has no UI to emulate.
- **`lib/common/`** — code shared by both MCUs: `protocol.h`/`protocol.c`, the inter-MCU UART frame format (`[SYNC 0x7E][TYPE][LEN][PAYLOAD...][CRC8]`, CRC8 over TYPE+LEN+PAYLOAD), the `wireless_state_t` struct (`MSG_STATE_UPDATE`, also used locally on the S3 for AirPlay state with `source = SOURCE_AIRPLAY`) and `track_info_t` (`MSG_TRACK_INFO`), plus the S3→ESP32 frames, `MSG_COMMAND` (`command_t`) and `MSG_DEVICE_NAME` (the Bluetooth name, raw UTF-8, ≤ `DEVICE_NAME_MAX`). It also holds the shared frame encoder (`protocol_encode()`) and byte-at-a-time parser (`protocol_parser_feed()`) both ends use — don't reimplement framing per MCU. Type 0x02 (the old ESP32→S3 NTP relay) is retired; don't reuse it. Auto-linked into every PlatformIO env — if you change the wire format, both `s3` and `esp32` firmware must agree, so edit it once here.

**Control ownership**: whichever MCU owns the active audio path (A2DP → ESP32; AirPlay/USB → S3) also owns its own encoder and volume state for that mode; the other MCU is a display/touch-passthrough peripheral. Don't add cross-MCU polling for input that already has an ownership rule — see spec.md's "Control ownership rule" for the reasoning.

**Source separation via `src/CMakeLists.txt`, not `build_src_filter`**: ESP-IDF's CMake build ignores PlatformIO's `build_src_filter` entirely (it silently globs all of `src/` otherwise) — the two MCU targets are separated by `src/CMakeLists.txt`, which each espidf env points at its half of the tree via `-DAK_TARGET=s3|esp32` (`board_build.cmake_extra_args` in `platformio.ini`). The glob is non-recursive; the S3 branch explicitly adds `s3/raop/` and `s3/alac/`. That file also has to declare a matching `idf_component_register()` call during ESP-IDF's "early expansion" pass (a separate `cmake -P` invocation that can't see `-DAK_TARGET`) or the real pass silently drops the component from the build — see the comments in that file before touching it. `env:native` doesn't go through any of this; it's plain PlatformIO source filtering (`platform = native`, not `espidf`).

**Per-env sdkconfig defaults**: `sdkconfig.defaults.esp32` (BT/A2DP) and `sdkconfig.defaults.s3` (16 MB flash, 8 MB octal PSRAM, `partitions_s3.csv`, 1 kHz FreeRTOS tick, socket count) live in the project root, wired in via the same `board_build.cmake_extra_args` (`-DSDKCONFIG_DEFAULTS=...`) — PlatformIO's `custom_sdkconfig` ini option is Arduino-only and silently no-ops under `framework = espidf`, so don't reach for it here. The S3 needs PSRAM enabled: `lcd_driver.c` allocates its draw buffers from it, and the AirPlay buffers (~1.3 MB) live there.

**esp32 A2DP sink** (`src/esp32/`): `bt_gap` brings up Bluedroid (Classic BT only, IO capability DisplayYesNo, 16-byte minimum encryption key); `bt_pairing` decides who may pair (see below); `a2dp_sink` handles connection/audio-state events and feeds decoded PCM to `i2s_out` (I2S TX on IO25/26/27, reconfigured per the negotiated SBC sample rate); `avrcp_target` is the absolute-volume target the phone pushes/pulls volume through; `avrcp_controller` sends play/pause passthrough commands from the local button (its "is it playing" state is a local guess, not authoritative — no metadata/registration wired up); `encoder` reads `EC2_A`/`EC2_B` via the PCNT quadrature decoder for local volume, and treats both lines going low at once as the `SW1` button (that's how it's wired — a short-to-GND across both encoder pins, not a separate GPIO); `app_state` is the single locked source of truth for the A2DP `wireless_state_t`, read by `state_sync` to push to the S3 over UART (33ms on change, unconditional resync every ~1s, per spec.md §2); `state_sync` also runs the UART RX task that hands `MSG_COMMAND` frames to `main.c` (`CMD_PAUSE` → AVRCP pause, or drop the A2DP link if the phone has no AVRCP controller); `bt_app_core` is the Bluedroid callback→task work-dispatch queue every BT/A2DP/AVRCP handler in this codebase re-enters through, vendored from Espressif's own (Unlicense/CC0) example code rather than hand-rolled. `bt_power` holds the Settings page's Bluetooth switch (owned by the S3, mirrored in ESP32 NVS so boot takes the right path): off, the ESP32 never starts Bluedroid and light-sleeps, woken by a low level on its UART RX (IO23 isn't an RTC pin, so no deep sleep); the waking frame is lost, so it sends `MSG_HELLO` and the S3 answers with the name and `CMD_BT_ENABLE`/`_DISABLE`. Toggling restarts the ESP32, with the DAC's XSMT pin held high through it so AirPlay keeps playing.

**Bluetooth pairing** (`src/esp32/bt_pairing.c`, `src/s3/ui_pairing.c`): the ESP32 is always connectable but discoverable only during a 2-minute window opened from the S3 (Settings › Pair a device, or tapping the icon on the Bluetooth waiting screen; `CMD_PAIRING_OPEN`). A phone pairing in the window gets a numeric-comparison code that the S3 shows over every screen (`MSG_PAIRING`'s `pairing_status_t`, resent every ~1 s like state) and the user accepts by tap or knob press (`CMD_PAIRING_ACCEPT`); rejecting closes the window. Confirmation requests outside the window are refused and legacy PIN pairing always is. Bluedroid completes Just Works pairing without asking the app, and reports a successful `AUTH_CMPL` only for a new link key, so any bond that completes outside the window is removed again (also covers a device spoofing a bonded address). A2DP and AVRCP require authentication, so an unbonded device gets no audio path without pairing. The ESP32 runs the state machine on the bt_app task; the S3 only renders it. Settings › Forget paired devices sends `CMD_FORGET_DEVICES`.

**s3 WiFi + NTP** (`src/s3/wifi.c`, `src/s3/wifi_portal.c`, `src/s3/ntp.c`): the only place in this repo that brings up WiFi. `wifi.c` joins as a station (power save off for AirPlay) using credentials from NVS namespace `wifi`, falling back to the optional dev-only `CONFIG_AK_WIFI_SSID`/`CONFIG_AK_WIFI_PASSWORD` (`src/Kconfig.projbuild`). With no credentials -- or none that connect within 60 s of boot -- it enters setup mode: APSTA with a WPA2 hotspot named after the device (random password per boot), shown on screen as a standard `WIFI:` join QR via `wifi_get_setup_info()` → `ui_show_wifi_setup()` (the setup screen becomes the UI's home screen). `wifi_portal.c` is the captive portal (DNS catch-all + HTTP setup page with the device name and network; everything else redirects to it so iOS/Android pop it up) and talks to `wifi.c` only through `wifi_portal_ops_t`; it and `web_settings.c` share `web_page.c`'s HTML helpers. Submitted credentials are tried live; on GOT_IP they're saved to NVS and the device restarts into normal mode. In setup mode saved credentials keep being retried every 30 s, so a router that boots slower than the device doesn't strand it. SNTP (`ntp.c`) sets the system clock itself and takes servers from DHCP (`CONFIG_LWIP_DHCP_GET_NTP_SRV`); `ntp_is_synced()` gates the clock display. Time is UTC everywhere except display.

**Device name** (`src/s3/device_name.c`): one user-chosen name (≤ 32 bytes UTF-8, NVS namespace `device`; first boot picks `AudioKnob-` + 8 random characters) is the AirPlay name, the Bluetooth name, the setup hotspot SSID and, slugified, the mDNS hostname. The S3 owns it: `main.c`'s change callback re-advertises AirPlay/mDNS live (`airplay_rename()`) and sends `MSG_DEVICE_NAME` to the ESP32, which `uart_link.c` repeats whenever the ESP32 reappears after >3 s of silence (the ESP32 doesn't persist it). It's set in the setup portal, or after setup on the device web page (below); the Settings page's Name and Web page rows show a QR to it by IP.

**s3 web page** (`src/s3/web_settings.c`, `src/s3/web/index.html`): on the home network at `http://<hostname>.local/` (not in setup mode, where the portal owns port 80). One static page, embedded with `EMBED_TXTFILES` in `src/CMakeLists.txt`, over a small JSON API: `GET /api/state` (every setting, the name, network/about info, now playing and Bluetooth pairing status, polled by the page every second), `/api/zones`, `/api/art.bmp` (the cover art as a 16-bit BMP, no encoder needed), and form POSTs `/api/set`, `/api/name`, `/api/volume`, `/api/transport`, `/api/pairing`, `/api/forget` (cross-origin POSTs refused). Settings go through `settings_ui_change()`/`settings_ui_snapshot()`, which take the LVGL lock and run the same path as the Settings page; playback goes through `now_playing`. The pairing code check stays on the device's screen.

**s3 AirPlay** — layered so each piece has one job:
- `src/s3/airplay/` — shared by both receivers behind `raop.h` (typed `raop_event_t`s and PCM with a per-frame playtime; knows nothing about the rest of the app). From philippe44's MIT-licensed squeezelite-esp32 `raop` component (attribution kept in each file): `raop_rtp.c` (HairTunes-derived AirPlay 1 RTP audio/control/timing, AES-CBC, reorder + resend, NTP sender clock sync, ALAC or L16 PCM per the SDP `rtpmap`), `raop_setup.c` (Apple-Challenge and the RSA-wrapped AES key via mbedtls, SDP/Transport/RTP-Info parsing), `dacp.c` (DACP remote discovery + commands), `http_util.c`; plus our own `dmap.c` (metadata) and `decoder.c` (ALAC and AAC on `esp_audio_codec`, the only decoders in the tree).
- `src/s3/airplay2/` — the default receiver (`CONFIG_AK_AIRPLAY2`): AirPlay 2 after shairport-sync with owntone's `pair_ap` (HomeKit transient pairing over libsodium/mbedtls), our own PTP follower, realtime (reorder window + resends) and buffered (TCP into a 1 MB PSRAM ring, AAC) streams. AirPlay 1 senders share its RTSP port 7000 as with shairport-sync: `ANNOUNCE` marks the connection AirPlay 1 and `ap1.c` takes its SETUP/RECORD/FLUSH/TEARDOWN, `session.c` keeps one playing sender across both protocols, and remote commands go over DACP or MediaRemote accordingly.
- `src/s3/airplay1/` — `raop.c`, the AirPlay 1-only receiver on port 5000 (`CONFIG_AK_AIRPLAY1`), on the shared pieces above.
- Internal RAM is what runs short while a buffered stream plays (AAC decode is ~5.5 ms per 1024-frame packet on core 0; ALAC ~0.5-1.3 ms per 352): `decoder.c` overrides esp_audio_codec's weak `media_lib_module_malloc`/`calloc`/`media_lib_free` hooks to put codec state (~50 KB for AAC) in PSRAM, at no cost in decode time, and lwIP keeps its default 4-MSS TCP window — an A/B with 32 KB held ~17 KB more internal RAM and came with playout drift and decode stalls, while the default kept the 1 MB ring fed. The mDNS task's stack is in PSRAM too (`CONFIG_MDNS_TASK_CREATE_FROM_SPIRAM`): nothing timing-critical, never writes flash.
- The Settings page's AirPlay 2 / AirPlay 1 switches pick the versions taken (`raop_set_protocols()`: unadvertised, new sessions refused, a running one of that version dropped); with none, the receiver isn't started, though mDNS still carries the hostname. Changes are applied 2 s after the last press, and only the records that change are touched: esp-mdns restarts probing on every service add and drops its queued packets, so a change mid-probe left it stuck with nothing announced. It sends one goodbye per removed record, which WiFi multicast sometimes loses; a stale picker entry then gets a 503.
- `airplay_player.c` — holds PCM until its playtime (~2 s ahead, PSRAM ring), writes it to `audio_out`, keeps it locked to the sender by trimming or repeating single samples (plus a learned feed-forward for the DAC's clock offset), re-aligns only past a 50 ms error, applies the cubic software volume.
- `airplay.c` — app glue: session/playing/volume/track state (`airplay_get_state()` returns a `wireless_state_t` so `ui_update_wireless()` renders it unchanged), DACP control task (knob volume coalesced, play/pause, preempt-pause).
- `audio_out.c` — S3 I2S TX on GPIO39/40/41, 44.1 kHz fixed; USB UAC2 should reuse it. `audio_source.c` — CH445P GPIO0 and "last source to start playing wins" arbitration (watches the ESP32's UART-reported `playing` edge; sends `CMD_PAUSE` when AirPlay displaces a playing A2DP stream). `knob.c` — S3 encoder EC1 + SW2. `now_playing.c` decides whose state is shown and whom the S3 knob, the touch transport and the web page drive (`now_playing_airplay_in_front()`), and holds the switch screen's manual pick.

**s3 UART link** (`src/s3/uart_link.c`): the S3 end of UART_NUM_1 (GPIO48 TX/GPIO38 RX; the schematic net names read the other way, verified on hardware). Its RX task parses frames with the shared parser and — per spec.md §2's decoupling design — only writes into shared state rather than calling into `ui.c` directly: `MSG_STATE_UPDATE` and `MSG_TRACK_INFO` frames land in mutex-guarded structs read via `uart_link_get_latest()` / `uart_link_get_latest_track()`. `uart_link_send_command()` sends `MSG_COMMAND` frames (fire-and-forget; the effect shows up in the next state update). Touch passthrough should add new `protocol_cmd_t` values rather than new frame types.

**Native LVGL target (`env:native`)**: only `src/s3/ui.c` + `src/s3/main_native.c` build here, against SDL2 (Homebrew, `pkg-config sdl2`) instead of the real QSPI LCD driver. `src/s3/ui.c` must stay platform-agnostic (LVGL API only — no ESP-IDF, no hardware headers) so it compiles unchanged for both the real S3 target and this emulator. `src/s3/main.c` (ESP-IDF, real hardware) and `src/s3/main_native.c` (SDL, desktop) are kept as separate entry-point files rather than one `#ifdef`-laden file, since `app_main()` vs `main()` have fundamentally different signatures and init sequences.

**UI fonts and source switching**: text uses Inter (OFL) pre-rasterized into `src/s3/font_inter_*.c` (declared in `fonts.h`; Montserrat stays for `LV_SYMBOL_*` glyphs). Regenerate with `lv_font_conv --bpp 4 --format lvgl --no-compress --lv-fallback lv_font_montserrat_14` from `@fontsource/inter` `.woff` files; native's `build_src_filter` picks them up via `+<s3/font_*.c>`. `inter_tnum_52`/`_26` (timer/stopwatch) are Inter Bold with its tabular figures baked in first by `tools/freeze_tnum.py`, since `lv_font_conv` applies no OpenType features. `icons_48`/`_20` are Material Symbols Rounded glyphs (weather, bulb), from the variable font instanced filled/weight 500 at each optical size. Tapping the wireless screen's status row opens the switch screen (AirPlay/Bluetooth; USB is not offered yet); `ui_set_source_handler()` reports the pick to `main.c`, which claims/releases the DAC through `audio_source` and holds the pick (`s_pick`) until the other source starts playing.

**Apps and navigation**: there is no swipe paging. The apps (lights, timer, tomato, stopwatch, weather, settings; order from `ui_app_t` in `ui_internal.h`) live in a launcher, `ui_launcher.c`: a ring of icons on `lv_layer_top()` over the current screen, opened by a long knob press (`knob.c` reports short presses on release, long ones at 500 ms) or a tap on the clock. Turning the knob walks the ring, a press (or tapping an icon) opens the app, and a second long press or a tap off the icons goes home; the pill on each app page goes home too, and an app page with nothing in progress goes home after 30 s idle. The clock shows a weather pill and a chip per app with something in progress (`ui_tools_status()`). A persistent audio chip, also on `lv_layer_top()`, sits at the top of the clock and every app page while a source is connected or playing, and a tap returns to its now-playing screen; opening an app sends a playing source to the background the same way a home swipe does. Each app is one `ui_<app>.c` on top of `ui_tools.c` — shared widgets, the page registry (each page's name, icon, tint and knob/status hooks) that ui.c and the launcher go through (`ui_tools_*()`), and `countdown_t`, the ringing countdown timer and tomato (pomodoro: 25/5 min, 15 min long break after every 4th completed focus) share, which keeps time as `lv_tick` deadlines rather than counted refreshes. The knob goes to `ui_knob_rotate()`/`ui_knob_press()` first (under the LVGL lock, from `main.c`'s knob callbacks) and only falls through to the volume of the source in front when they return false (AirPlay directly; Bluetooth via `CMD_VOLUME_UP`/`_DOWN`, one frame per detent; a press still only reaches AirPlay) (weather, the clock, and the stopwatch's rotate don't use it). A ringing countdown pulls its page forward and blocks `surface_source()` until dismissed (tap, knob press, leaving the page, or 60 s); `ui_set_alert_handler()` lets `main.c` run a repeating DRV2605 buzz meanwhile, unless haptics are off in settings (`haptic.c`, I2C-only on the touch bus via `lcd_driver_i2c_bus()`; EN/TRIG aren't on any S3 GPIO, matching Waveshare's own demo). Data reaches the weather/lights/settings pages only through `ui_update_weather()`/`ui_update_lights()`/`ui_update_settings()`, and user changes leave through the lights/settings handlers. In `env:native` Up/Down arrows turn the knob, Enter presses it, and holding Enter or pressing Esc long-presses it (the mouse wheel works too); there is no fake playback state, so the now-playing screens only appear on hardware, but the weather page gets a fixed sample (labelled "Sample data") and settings live in memory, with "automatic" timezone meaning the host's.

**s3 online services, settings, lights**: `online.c` runs one task (8 KB internal stack, response bodies and cJSON nodes in PSRAM) that waits for the first got-IP, locates the device by IP (`geo.c`: ipwho.is, falling back to ipinfo.io; every 12 h, skipped while a manual location is pinned), then fetches Open-Meteo (`weather.c`, every 15 min, with backoff on failure), all over HTTPS via `http_get.c` and the IDF certificate bundle; `main.c` polls `online_get_weather()`'s version into the UI. The detected location and the manual one (picked on the web page through Open-Meteo's geocoder, called from the phone; the device's Location row can only go back to automatic) are kept in NVS namespace `location`, loaded in `online_start()`, so the timezone applies at boot before any network; NVS writes happen on the online task. `settings_ui.c` loads/saves `settings.c` (NVS namespace `settings`, writes debounced 2 s), applies backlight and timezone, and handles the Settings page (`ui_settings.c`: a wheel of rows under section headers, the selected row held in a fixed highlight mid-screen and the rest fading with distance via per-label `text_opa`, since a whole-row `opa` would render each row through a layer); the timezone is the manual pick if any, else the location's zone. newlib's `tzset()` needs POSIX rules, not IANA names, so `tz_db.c` (generated by `tools/gen_tz_db.py` from the host's `/usr/share/zoneinfo`, footer line of each TZif file) maps them, with a fixed-offset fallback (`tz_apply_offset()`) for zones it lacks. Lights go through `lights.h`; WiZ bulbs (UDP JSON on port 38899) are the target, but `lights_mock.c` — three in-memory bulbs, built for native too — stands in for now; `lights_ui.c` polls the backend into the page.

`include/lv_conf.h` is the one shared config both `s3` and `native` compile against; the single point of divergence (`LV_USE_SDL`) is gated behind `#ifdef AK_NATIVE`, defined only in `env:native`'s `build_flags`. Don't fork this file — add new native-only behavior the same way, behind `AK_NATIVE`. `env:s3` needs `lv_conf.h` visible to the `lvgl` library too, which (being a plain PlatformIO lib, not an ESP-IDF component that requires ours) can't see project's `include/` by default — `src/CMakeLists.txt` adds it to every component's compile flags via `idf_build_set_property(COMPILE_OPTIONS ...)` for that reason; don't remove it.

On real hardware `src/s3/lcd_driver.c` brings up the ST77916 QSPI panel, CST816S touch and the LVGL task. Three panel quirks it handles, all learned from garbled output: the panel needs Waveshare's own init table (`lcd_init_cmds.h`, not the driver default), every flush window must start on an even and end on an odd pixel (LVGL rounder on `LV_EVENT_INVALIDATE_AREA`), and the panel takes big-endian RGB565, so LVGL renders `LV_COLOR_FORMAT_RGB565_SWAPPED` directly (full-screen RGB565 images such as the wallpaper are swapped when copied into PSRAM to keep their blit a memcpy); QSPI runs at 80 MHz like Waveshare's stock firmware (`CONFIG_AK_LCD_PCLK_MHZ`), with one 60-line draw buffer in internal DMA RAM. The LVGL task runs at priority 7 on core 1, below AirPlay's RTP (8) and player (15) tasks there, and sleeps `lv_timer_handler()`'s hint clamped to 2-10 ms; `LV_DEF_REFR_PERIOD` is 10 ms. `main.c` calls `ui_init()` under the LVGL lock and polls state into `ui_update_*()` on a 33 ms LVGL timer.

**LVGL rendering cost** (LVGL 9.6): `lv_mem_esp.c` puts all of LVGL's heap in PSRAM (`LV_STDLIB_CUSTOM`; 9.6's built-in pool would be internal .bss, and render-time scratch in internal RAM measured no gain). Software rendering costs roughly the area an object's masks cover, not its visible pixels: an arc or rounded shape is masked across its whole bounding box (a 344 px ring ~8-13 ms per full frame, an empty screen ~10 ms, mostly the flush), and a full-screen image costs ~8 ms to copy out of PSRAM, so baking whole screens doesn't pay. Hence the tool rings draw no track, only progress, and no gradient or rounded shape is drawn live behind the now-playing screens: `tools/gen_backgrounds.py` renders the clock wallpaper and, per source tint, a full-screen background with the radial wash and the rounded gradient art tile baked in, Bayer-dithered to RGB565 (LVGL's gradients band), into `src/s3/ui_bg_data.{c,h}`; `ui_backgrounds.c` copies them from flash into PSRAM, and cover art drawn square over the tile is rounded by four small ARGB8888 corner overlays from the same script (ARGB8565 can't blend onto the swapped panel format). Rerun the script after moving or resizing the tile; `ui.c` static-asserts the geometry. `CONFIG_AK_LVGL_PERF_LOG` (off by default) benchmarks this: it forces full redraws, cycles every screen, and logs each screen's frame time and what each top-level child costs. USB audio isn't implemented, so its now-playing screen is compiled out unless `AK_USB_AUDIO` is defined.

## Toolchain notes

- ESP-IDF framework (via PlatformIO), not Arduino — Arduino-ESP32's TinyUSB build doesn't compile `CFG_TUD_AUDIO`, so USB Audio Class (Mode B) requires ESP-IDF.
- `env:s3` and `env:esp32` boards (`esp32-s3-devkitc-1`, `esp32dev`) are generic placeholders. The S3's real flash/PSRAM config comes from `sdkconfig.defaults.s3` (16 MB / 8 MB octal); the ESP32-U4WDH side's (4 MB embedded flash, no PSRAM) from `sdkconfig.defaults.esp32` + `partitions_esp32.csv` (3 MB factory app; Bluedroid alone is ~1 MB).
- `env:native` requires SDL2 on the host (`brew install sdl2` on macOS); its `build_flags` hardcode Homebrew's `/opt/homebrew` prefix.
